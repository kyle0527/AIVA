# 服務骨幹模組詳細說明

## 概念解釋

### 什麼是"能力"？
**能力 = 起點腳本 → 終點腳本**

例如：`session_state_manager → app` 是一個能力

### 什麼是"數據流"？
**數據流 = 從起點到終點的完整路徑（包含中間經過的所有腳本）**

### 什麼是"多路徑"？
**同一個能力（相同起點和終點），但中間經過的腳本不同**

---

## 服務骨幹具體情況

### 基本統計
- **37個獨特能力** = 37個不同的"起點→終點"組合
- **163條數據流** = 這37個能力加起來總共有163條路徑
- **20個有多路徑** = 37個能力中，有20個擁有2條以上的路徑
- **17個單一路徑** = 37個能力中，有17個只有1條路徑

### 能力類型分布
在這37個獨特能力中：
- **1個 AI內部能力**
- **2個 對外能力**
- **34個 混合能力**

## 為什麼會混淆？

很多人會以為：
- ❌ "37個能力有多路徑" = 37個能力都有多個版本
- ❌ "163條數據流" = 163個不同的能力

實際上是：
- ✓ **37個能力** = 37種不同的起點→終點組合
- ✓ **163條數據流** = 這37個能力的所有路徑版本加總
- ✓ **20個有多路徑** = 其中20個能力有≥2條數據流
- ✓ **17個單一路徑** = 其中17個能力只有1條數據流

---

## 類比說明

想像一個城市的交通系統：

- **能力** = 從A地到B地（例如：從家到公司）
- **數據流** = 具體的路線（例如：走大馬路、走小巷子、坐地鐵）
- **多路徑** = 有多種不同的走法

**服務骨幹模組**就像：
- 有37個目的地配對（37個能力）
- 總共有163條不同的路線（163條數據流）
- 其中20個目的地配對有多條路線可選（20個多路徑能力）
- 其中17個目的地配對只有1條路線（17個單一路徑能力）

## 總結

服務骨幹模組的完整情況：

```
37個能力 = 20個多路徑 + 17個單一路徑

163條數據流分配：
  - 20個多路徑能力包含：146條數據流
  - 17個單一路徑能力包含：17條數據流
  
能力類型（基於終點腳本功能）：
  - AI內部能力：1個
  - 對外能力：2個
  - 混合能力：34個
```
