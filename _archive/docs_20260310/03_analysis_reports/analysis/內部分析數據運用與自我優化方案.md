## 🎯 二、能力編排機制

### 2.1 核心組件: CapabilityOrchestrator

**位置**: `services/core/aiva_core/cognitive_core/capability_orchestrator.py`

**職責**:
1. ✅ 理解任務需求
2. ✅ 查詢 RAG 找到相關能力
3. ✅ 智能選擇最佳能力組合
4. ✅ 生成可執行的 AICommand 序列
5. ✅ 監控執行並學習優化

### 2.2 工作流程

```python
# Step 1: 定義任務需求
requirement = TaskRequirement(
    task_id="task_001",
    task_type="comprehensive_scan",  # scan | attack | comprehensive
    target="https://example.com",
    objectives=["find_vulnerabilities", "test_xss", "test_sqli"],
    constraints={"max_depth": 3, "timeout": 600}
)

# Step 2: 生成執行計劃 (AI 決策)
orchestrator = CapabilityOrchestrator()
plan = await orchestrator.plan(requirement)

# Step 3: 執行計劃
result = await orchestrator.execute(plan)

# Step 4: 學習優化
await orchestrator.learn_from_execution(plan, result)
```

### 2.3 計劃生成流程 (plan 方法)

```
1. 查詢 RAG 找到相關能力
   ├─ 構建查詢: "Task: comprehensive_scan | Objectives: find_vulnerabilities, test_xss"
   ├─ RAG 語義搜索 (top_k=20)
   └─ 返回相關能力列表

2. 過濾可用能力
   ├─ 檢查 health_score >= 0.5
   ├─ 檢查 availability >= 0.7
   └─ 過濾掉不健康的能力

3. 選擇最佳能力組合
   ├─ 計算每個能力的評分:
   │   ├─ 任務匹配度 (40%): 關鍵字匹配
   │   ├─ 健康狀態 (30%): health_score + availability
   │   └─ 歷史性能 (30%): success_rate - latency_penalty
   ├─ 按分數排序
   └─ 選擇 top N (default=5)

4. 生成執行序列
   ├─ 掃描任務: Phase0 → Phase1 → 專項掃描
   ├─ 攻擊任務: 低風險 → 中風險 → 高風險
   └─ 綜合任務: 掃描 → 分析 → 攻擊

5. 轉換為 AICommand
   ├─ 映射能力到 CommandType (SCAN_PHASE0, FEATURE_XSS_TEST, ...)
   ├─ 構建 payload (target, task_id, constraints)
   └─ 生成命令列表

6. 評估風險和耗時
   └─ 返回 CapabilityPlan
```

## 📈 四、自我優化機制

### 4.1 性能統計追蹤

**數據結構**: `capability_performance`

```python
{
  "cap-scan-phase0": {
    "total_executions": 150,
    "successful_executions": 145,
    "failed_executions": 5,
    "total_latency_ms": 225000,
    "avg_latency_ms": 1500,
    "success_rate": 0.967
  }
}
```

### 4.2 學習流程 (learn_from_execution)

```python
async def learn_from_execution(plan, result):
    """從每次執行學習"""
    
    for capability in plan.selected_capabilities:
        cap_id = capability["metadata"]["capability_id"]
        
        # 1. 更新執行次數
        stats["total_executions"] += 1
        
        # 2. 判斷成功/失敗
        if capability in result.completed_commands:
            stats["successful_executions"] += 1
        else:
            stats["failed_executions"] += 1
        
        # 3. 重新計算成功率
        stats["success_rate"] = (
            successful / total_executions
        )
        
        # 4. 更新平均延遲
        stats["avg_latency_ms"] = (
            total_latency / total_executions
        )
```

### 4.3 優化效果

**初次執行** (無歷史數據):
- 所有能力 success_rate 預設 0.8
- 選擇主要基於任務匹配度 (40%) 和健康狀態 (30%)

**多次執行後** (有歷史數據):
- 成功率高的能力得分提升 → 更常被選中
- 延遲高的能力被懲罰 → 較少被選中
- 失敗率高的能力自然淘汰

**範例**:
```
能力 A: success_rate=0.95, avg_latency=800ms  → 高分
能力 B: success_rate=0.60, avg_latency=1200ms → 低分
能力 C: success_rate=0.90, avg_latency=5500ms → 中分 (延遲懲罰)
```

## 🛠️ 六、能力評分算法

### 6.1 評分公式

```python
total_score = (
    match_score * 0.4 +      # 任務匹配度 40%
    health_score * 0.3 +     # 健康狀態 30%
    performance_score * 0.3  # 歷史性能 30%
)
```

### 6.2 任務匹配度 (match_score)

```python
match_score = 0.0

for objective in task.objectives:
    if objective in capability.name:
        match_score += 1.0  # 名稱完全匹配
    elif objective in capability.description:
        match_score += 0.5  # 描述部分匹配

# 歸一化
match_score = min(match_score / len(objectives), 1.0)
```

### 6.3 健康狀態 (health_score)

```python
health_score = (
    capability.health_score +      # 能力健康分數 (0-1)
    capability.availability        # 可用性 (0-1)
) / 2
```

### 6.4 歷史性能 (performance_score)

```python
# 成功率
success_rate = successful_executions / total_executions

# 延遲懲罰 (超過 5 秒開始懲罰)
latency_penalty = max(0, (avg_latency_ms - 5000) / 5000)
latency_penalty = min(latency_penalty, 0.5)  # 最多扣 50%

performance_score = success_rate * (1 - latency_penalty)
```

### 6.5 評分範例

**能力 A** (XSS 測試):
- 任務: "comprehensive_scan" + objectives=["test_xss", "find_vulnerabilities"]
- match_score: 1.0 (完全匹配 "test_xss")
- health_score: 0.95 (health=1.0, availability=0.9)
- performance_score: 0.90 (success_rate=0.95, latency=1200ms, 無懲罰)
- **total_score = 0.4 * 1.0 + 0.3 * 0.95 + 0.3 * 0.90 = 0.955** ✅

**能力 B** (SQL 注入):
- match_score: 0.0 (不匹配 "test_xss")
- health_score: 0.90
- performance_score: 0.85
- **total_score = 0.4 * 0.0 + 0.3 * 0.90 + 0.3 * 0.85 = 0.525** ❌

## 🎓 七、自我優化案例

### Case 1: 新能力初期表現差

**情境**: 新增 "advanced_xss_fuzzing" 能力

**初期** (無歷史):
- success_rate: 0.8 (預設)
- 被選中機率: 中等

**執行 10 次後**:
- 成功 9 次,失敗 1 次
- success_rate: 0.9
- 被選中機率: ↑ 提升

**執行 100 次後**:
- 成功 95 次,失敗 5 次
- success_rate: 0.95
- avg_latency: 800ms
- 被選中機率: ↑↑ 大幅提升,成為首選

### Case 2: 老舊能力性能下降

**情境**: "legacy_port_scanner" 能力老化

**初期**:
- success_rate: 0.85
- avg_latency: 2000ms

**一段時間後**:
- success_rate: 0.60 (頻繁失敗)
- avg_latency: 5500ms (延遲增加)
- performance_score: 0.60 * (1 - 0.1) = 0.54
- 被選中機率: ↓↓ 大幅下降

**結果**: 系統自動減少使用該能力,轉向新的替代方案

### Case 3: 執行順序優化

**情境**: 綜合掃描任務

**初期順序** (基於類別):
1. port_scan (掃描類)
2. service_detect (掃描類)
3. xss_test (攻擊類)
4. sqli_test (攻擊類)

**多次執行後發現**:
- xss_test 在 service_detect 前執行效果更好
- sqli_test 需要 port_scan 的結果

**優化後順序**:
1. port_scan (必須先執行)
2. xss_test (利用 port_scan 結果)
3. service_detect (補充信息)
4. sqli_test (基於前面的結果)

## 🔧 八、與現有系統整合

### 8.1 與 BioNeuron 整合

```python
# BioNeuron 負責 NLU (自然語言理解)
user_input = "掃描 example.com 找出 XSS 漏洞"

# BioNeuron 解析
intent = bio_neuron.parse(user_input)
# 返回: {"action": "scan", "target": "example.com", "focus": "xss"}

# CapabilityOrchestrator 負責決策
requirement = TaskRequirement(
    task_id=generate_id(),
    task_type="scan",
    target=intent["target"],
    objectives=[intent["focus"]]  # ["xss"]
)

plan = await orchestrator.plan(requirement)
result = await orchestrator.execute(plan)
```

### 8.2 與 AICommandCenter 整合

```python
# CapabilityOrchestrator 生成 AICommand
commands = plan.commands  # List[AICommand]

# AICommandCenter 執行命令
from aiva_common.command_center import AICommandCenter
command_center = AICommandCenter()

for command in commands:
    result = await command_center.execute(command)
    # 命令會路由到對應模組的 CommandHandler
```

### 8.3 資料流整合

```
User → BioNeuron (NLU) → CapabilityOrchestrator (決策)
         ↓                       ↓
      Intent              CapabilityPlan
                                ↓
                        AICommand List
                                ↓
                        AICommandCenter (執行)
                                ↓
                         Module Handlers
                                ↓
                          實際執行引擎
                                ↓
                        AICommandResult
                                ↓
                    CapabilityOrchestrator (學習)
```
