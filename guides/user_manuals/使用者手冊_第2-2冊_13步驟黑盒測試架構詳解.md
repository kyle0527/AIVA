## 1. 為什麼需要規劃與執行分離

### 1.1 核心原則

```
步驟 N 的輸出 → 步驟 N+1 的輸入依據
```

**錯誤做法** ❌：
```python
# 直接執行，沒有規劃
async def bad_reconnaissance(target):
    # 只做一件事，資訊不足
    response = await httpx.get(target)
    return {"status": response.status_code}
```

**正確做法** ✅：
```python
# Step 3: 先規劃多個探查任務
tasks = plan_phase0_tasks(target)
# → [httpx, port_scan, waf_detect, tech_stack, dir_scan]

# Step 4: 執行所有任務
results = await execute_parallel(tasks)
# → 5 個結果

# Step 5: 整合所有情報
integrated = integrate_results(results)
# → 統一情報視圖

# Step 6: AI 基於完整情報決策
decision = await ai_decide(integrated)
```

### 1.2 為什麼要分開？

| 步驟 | 職責 | 為什麼重要 |
|------|------|-----------|
| **Step 3: 規劃** | 決定要探查什麼 | 根據目標特性制定策略 |
| **Step 4: 執行** | 實際執行探查 | 高性能並行執行（Rust） |
| **Step 5: 整合** | 合併所有結果 | 提供完整情報給 AI |
| **Step 6: 決策** | AI 分析並決策 | 基於完整資訊做智能判斷 |

## 2. 黑盒測試的核心理念

### 2.1 什麼是黑盒測試？

```
黑盒 = 完全不知道目標內部情況
```

**面臨的問題**：
- ❓ 不知道開了哪些端口
- ❓ 不知道用什麼技術棧
- ❓ 不知道有沒有 WAF
- ❓ 不知道目錄結構
- ❓ 不知道 API 端點

**解決方案**：多路並行探查

### 2.2 多路並行探查策略

```
                    目標網站
                       ↓
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
   探查任務 1      探查任務 2      探查任務 3
   (HTTP 探測)    (端口掃描)      (WAF 檢測)
        ↓              ↓              ↓
        └──────────────┼──────────────┘
                       ↓
              整合所有結果
                       ↓
                  AI 決策
```

**為什麼要並行？**

1. **節省時間**: 5 個任務並行比順序執行快 5 倍
2. **提高成功率**: 某個探查失敗不影響其他
3. **互補性**: 不同角度的探查互相補充資訊

## 4. 關鍵步驟詳解

### 4.1 Step 3: 規劃多路並行探查

**代碼實現**：
```python
async def _plan_phase0_tasks(self, target: str) -> list[dict[str, Any]]:
    """步驟 3: 規劃 Phase 0 多路並行探查任務
    
    黑盒測試策略：因為不知道目標情況，所以規劃多個不同角度的探查
    """
    tasks = [
        {
            "task_id": "phase0_http_probe",
            "tool": "httpx",
            "description": "HTTP 基礎探測",
            "parameters": {"target": target, "follow_redirects": True}
        },
        {
            "task_id": "phase0_port_scan",
            "tool": "port_scanner",
            "description": "端口掃描",
            "parameters": {"target": target, "ports": "top100"}
        },
        {
            "task_id": "phase0_waf_detect",
            "tool": "waf_detector",
            "description": "WAF 檢測",
            "parameters": {"target": target}
        },
        {
            "task_id": "phase0_tech_fingerprint",
            "tool": "tech_stack",
            "description": "技術棧指紋",
            "parameters": {"target": target}
        },
        {
            "task_id": "phase0_dir_discover",
            "tool": "directory_scanner",
            "description": "目錄發現",
            "parameters": {"target": target, "wordlist": "common"}
        }
    ]
    
    logger.info(f"   📝 規劃 {len(tasks)} 個並行探查任務")
    return tasks
```

**設計考量**：
- ✅ **獨立性**: 每個任務可以獨立執行
- ✅ **互補性**: 不同角度的資訊互相補充
- ✅ **可擴展**: 可以輕鬆添加新的探查類型

### 4.2 Step 4: 執行並行探查

**代碼實現**：
```python
async def _execute_parallel_tasks(
    self, 
    tasks: list[dict[str, Any]]
) -> list[dict[str, Any]]:
    """步驟 4: 並行執行多個探查任務
    
    使用 UnifiedExecutor 或直接調用工具（降級模式）
    """
    results = []
    
    # 如果有 UnifiedExecutor，使用它來執行
    if self.unified_executor:
        logger.info(f"   🚀 使用 UnifiedExecutor 執行 {len(tasks)} 個任務")
        
        # TODO: 實際應該並行執行
        for task in tasks:
            try:
                result = await self._execute_single_task(task)
                results.append(result)
            except Exception as e:
                logger.warning(f"   ⚠️ 任務 {task['task_id']} 失敗: {e}")
                results.append({
                    "task_id": task["task_id"],
                    "success": False,
                    "error": str(e)
                })
    else:
        # 降級模式：使用簡化的本地執行
        logger.warning(f"   ⚠️ UnifiedExecutor 不可用，使用降級模式")
        for task in tasks:
            result = await self._fallback_execute_task(task)
            results.append(result)
    
    return results
```

**執行策略**：
- 🎯 **優先使用 Rust 引擎**: 高性能並行執行
- 🔄 **降級模式**: Python httpx 本地執行
- 🛡️ **容錯處理**: 單個任務失敗不影響整體

### 4.3 Step 5: 整合多路結果

**代碼實現**：
```python
async def _integrate_phase0_results(
    self, 
    results: list[dict[str, Any]]
) -> dict[str, Any]:
    """步驟 5: 整合多路探查結果
    
    將多個並行探查的結果整合成統一的情報
    """
    integrated = {
        "open_ports": [],
        "technologies": [],
        "waf_detected": False,
        "directories_found": [],
        "http_info": {},
        "raw_results": results
    }
    
    for result in results:
        if not result.get("success"):
            continue
        
        tool = result.get("tool", "")
        data = result.get("data", {})
        
        # 根據工具類型整合數據
        if tool == "httpx":
            integrated["http_info"] = {
                "status_code": data.get("status_code"),
                "headers": data.get("headers", {})
            }
            # 從 headers 提取技術棧
            headers = data.get("headers", {})
            if "x-powered-by" in headers:
                integrated["technologies"].append(headers["x-powered-by"])
            if "server" in headers:
                integrated["technologies"].append(headers["server"])
        
        elif tool == "port_scanner":
            integrated["open_ports"] = data.get("open_ports", [])
        
        elif tool == "waf_detector":
            integrated["waf_detected"] = data.get("waf_detected", False)
        
        elif tool == "tech_stack":
            integrated["technologies"].extend(data.get("technologies", []))
        
        elif tool == "directory_scanner":
            integrated["directories_found"] = data.get("directories", [])
    
    # 去重技術棧
    integrated["technologies"] = list(set(integrated["technologies"]))
    
    logger.info(f"   ✅ 整合完成: {len(results)} 個結果 → 1 個統一情報")
    
    return integrated
```

**整合邏輯**：
- 📊 **按工具分類**: 不同工具的數據存放到不同欄位
- 🔗 **關聯分析**: 從 HTTP headers 提取技術棧資訊
- 🧹 **數據清洗**: 去重、格式化

### 4.4 Step 6: AI 決策基於完整情報

**關鍵差異**：
```python
# ❌ 錯誤：基於不完整的單一探查結果
phase1_decision = await ai.decide(http_response_only)

# ✅ 正確：基於整合後的多路情報
phase1_decision = await ai.decide(phase0_integrated)
```

**AI 可見的完整情報**：
```json
{
  "open_ports": [80, 443, 3306],
  "technologies": ["PHP", "Laravel", "MySQL"],
  "waf_detected": true,
  "directories_found": ["/admin", "/api"],
  "http_info": {
    "status_code": 200,
    "headers": {...}
  }
}
```

**AI 決策邏輯**：
1. 看到 3306 端口開放 → MySQL 存在，SQL 注入風險高
2. 看到 /admin 目錄 → 可能有權限提升機會
3. 看到 WAF → 需要隱匿模式
4. 看到 Laravel → 已知漏洞模式

## 5. 實戰案例分析

### 5.1 案例：掃描 Juice Shop

**Step 3: 規劃的 5 個任務**：
```
1. HTTP 探測 → 確認服務可達性
2. 端口掃描 → 發現 3000 (HTTP)
3. WAF 檢測 → 無 WAF
4. 技術棧 → 發現 Express.js, Angular
5. 目錄掃描 → 發現 /api, /rest
```

**Step 4: 並行執行結果**：

    "data": {"waf_detected": false}
  },
  {
    "task_id": "phase0_tech_fingerprint",
    "success": true,

    "task_id": "phase0_dir_discover",

**Step 5: 整合結果**：

### 5.2 性能對比

**舊方式（順序執行）**：
```
HTTP 探測 (3s)
  → 端口掃描 (5s)
    → WAF 檢測 (2s)
      → 技術棧 (3s)
        → 目錄掃描 (10s)
          
總時間: 23 秒
```

**新方式（並行執行）**：
```
HTTP 探測 (3s) ┐
端口掃描 (5s)  ├─ 並行
WAF 檢測 (2s)  ├─ 執行
技術棧 (3s)    ├─ 
目錄掃描 (10s) ┘

總時間: 10 秒（最長任務的時間）
```

**效能提升**: 2.3 倍

## 6. 性能與優化

### 6.1 Rust 引擎的角色

**為什麼需要 Rust？**

```python
# Python: 單線程，GIL 限制
async def slow_scan():
    tasks = [scan1(), scan2(), scan3()]
    results = await asyncio.gather(*tasks)
    # 受限於 I/O 和 GIL

# Rust: 真正的並行，無 GIL
fn fast_scan() {
    let tasks: Vec<_> = (0..100)
        .map(|i| tokio::spawn(scan_task(i)))
        .collect();
    // 真正的多線程並行
}
```

**性能對比**：
- Python: 100 個任務 ≈ 30 秒
- Rust: 100 個任務 ≈ 5 秒
- **提升**: 6 倍

### 6.2 優化建議

1. **任務粒度**: 每個任務 < 10 秒
2. **超時設置**: 避免某個任務卡住整體
3. **錯誤處理**: 單個任務失敗不影響其他
4. **結果緩存**: 避免重複探查

### 7.1 核心要點

✅ **規劃與執行分離**: Step 3 規劃，Step 4 執行，Step 5 整合

- [ ] Step 3 是否規劃了足夠的並行任務？
