## 1. 概述：從決策到執行

經過第2冊的 AI 決策流程後，系統已產生經過驗證的參數 JSON。本冊說明如何將這些參數轉換為實際 CLI 命令並執行。

```
第2冊輸出: {"mode": "stealth", "target": "example.com", ...}
     ↓
第3冊: 組裝 → 執行 → 適應
     ↓
最終結果: 掃描報告
```

### 1.1 執行系統核心模組

執行與適應由以下核心檔案實現：

| 檔案 | 位置 | 職責 |
|------|------|------|
| `app.py` | `service_backbone/api/` | FastAPI 入口，啟動時建立並注入執行器 |
| `dispatcher.py` | `cognitive_core/` | 核心派發器，路由任務到對應處理器 |
| `execution_orchestrator.py` | `cognitive_core/decision/` | 執行編排器，協調多步驟執行流程 |
| `__init__.py` (Commander) | `task_planning/commander/` | CommanderCoordinator，接收注入的執行器 |
| `attack_coordinator.py` | `task_planning/commander/` | AttackCoordinator，使用注入的執行器執行攻擊 |
| `unified_executor.py` | `task_planning/` | 統一執行器，整合內部/外部執行 |

#### 執行流程架構（依賴注入模式）

```
app.py (啟動時)
    ├── 創建 UnifiedAttackExecutor
    ├── 創建 MultiEngineCoordinator  
    ├── 創建 InternalLoopConnector
    └── 注入到 CommanderCoordinator
         ↓
CommanderCoordinator (接收依賴)
    ├── unified_executor (注入)
    ├── multilang_coordinator (注入)
    ├── internal_loop_connector (注入)
    └── 創建子模組時傳遞執行器
         ↓
AttackCoordinator (接收依賴)
    ├── unified_executor (來自 Commander)
    ├── multilang_coordinator (來自 Commander)
    └── internal_loop (來自 Commander)
         ↓
實際執行任務
```

#### 指揮鏈流程（正確版本）

```
HTTP 請求
    ↓
app.py (FastAPI 入口)
    ↓
EnhancedDecisionAgent (AI 決策)
    ├── 分析目標
    ├── 選擇策略
    └── 生成執行計畫
    ↓
CommanderCoordinator (指揮協調)
    ├── 使用注入的 unified_executor
    ├── 使用注入的 multilang_coordinator
    └── 創建 AttackCoordinator 並傳遞執行器
         ↓
AttackCoordinator (攻擊協調)
    ├── coordinate_attack() 協調攻擊流程
    ├── 使用 unified_executor.execute() 執行
    └── 使用 multilang_coordinator.execute() 多語言執行
         ↓
UnifiedAttackExecutor (統一執行)
    ├── 內部執行器 (Python 模組)
    └── 外部執行器 (CLI 命令)
         ↓
MultiEngineCoordinator (多引擎協調)
    ├── Python Engine
    ├── Go Engine
    ├── Rust Engine
    └── TypeScript Engine
         ↓
掃描結果返回
```

#### 依賴注入關鍵點

1. **app.py startup()**：
   - 在啟動時創建所有執行器實例
   - 將執行器注入到 CommanderCoordinator
   - 確保整個指揮鏈使用相同的執行器實例

2. **CommanderCoordinator.__init__()**：
   - 接收 unified_executor、multilang_coordinator、internal_loop_connector
   - 使用惰性加載創建子模組（attack_coordinator）
   - 傳遞執行器給子模組

3. **AttackCoordinator.__init__()**：
   - 簡化為只接收 3 個核心依賴
   - 不再內部創建執行器
   - 直接使用注入的執行器實例

## 2. Step 7-8: 命令組裝

### Step 7: 路徑解析

CommandBuilder 將參數 JSON 轉換為 CLI 命令：

```python
# 從 paths_config.py 取得工具路徑
tool_path = "/usr/local/bin/aiva-scanner"

# 輸入參數
params = {"target": "example.com", "mode": "stealth", "concurrency": 2}
```

### Step 8: 參數拼接

將 JSON 轉換為命令列字串：

| 參數類型 | JSON 值 | CLI 轉換 |
|---------|--------|---------|
| 字串 | `"example.com"` | `--target example.com` |
| 列舉 | `"stealth"` | `--mode stealth` |
| 整數 | `2` | `--concurrency 2` |
| 布林 | `true` | `--safe-check` (flag 存在) |
| 布林 | `false` | (flag 不存在) |

**最終命令**：
```bash
/usr/local/bin/aiva-scanner --target example.com --mode stealth --concurrency 2 --safe-check
```

### 掃描階段說明

AIVA 掃描分為兩個階段：

#### Phase 0: 快速偵察 (5-10 分鐘)

```
1. 端口掃描
   - 常見端口 (Top 1000)
   - 服務版本識別
   
2. Web 服務檢測
   - HTTP/HTTPS 識別
   - Web 伺服器類型
   - 框架指紋
   
3. 基礎安全檢查
   - SSL/TLS 配置
   - 常見安全標頭
   - robots.txt 分析
```

**CLI 使用**:
```bash
python aiva_cli.py --attack "快速掃描 http://localhost:3000"
```

#### Phase 1: 深度掃描 (10-30 分鐘)

```
1. 漏洞檢測
   - SQL 注入
   - XSS (跨站腳本)
   - CSRF
   - 文件上傳漏洞
   
2. 配置檢查
   - 敏感檔案暴露
   - 目錄遍歷
   - 弱密碼
   
3. 攻擊面評估
   - 輸入點分析
   - API 端點掃描
   - 參數篡改測試
```

**預期輸出**:
```
🔎 開始 Phase 1 深度掃描...

[1/3] 漏洞檢測
✓ SQL 注入測試: 發現 3 個注入點
✓ XSS 測試: 發現 2 個反射型 XSS
✗ CSRF 測試: 未發現

Phase 1 完成 (用時: 25 分鐘)
發現 11 個漏洞 (高危: 5, 中危: 4, 低危: 2)
```

## 4. Step 10-12: 策略調整與重試

### Step 10: 結果分析

執行完成後，系統分析結果：

| Exit Code | 狀態 | 處置 |
|-----------|------|------|
| 0 | 成功 | 返回結果 |
| 1 | 策略失敗 | 進入 Step 11 |
| 2+ | 程式錯誤 | 報錯終止 |

### Step 11: Strategy Engine 介入

當掃描失敗時（例如被 WAF 攔截）：

```
Stdout: "WAF detected, IP blocked"
Exit Code: 1
     ↓
Strategy Engine 分析:
- 原因: WAF 偵測
- 可能解法: 增加延遲、更換 User-Agent
     ↓
重新查詢 Decision Agent
```

### Step 12: 參數變異

AI 根據失敗原因調整參數：

```json
// 原參數
{"mode": "quick", "concurrency": 10}

// 變異後
{
  "mode": "stealth",
  "concurrency": 2,
  "delay": "2000",        // 新增
  "random-agent": true    // 新增
}
```

**然後回到 Step 7 重新組裝命令**

## 5. 錯誤處理與日誌

### 日誌位置

```
logs/
├── aiva_core/
│   └── app.log          # Core API 日誌
├── cli/
│   └── execution.log    # CLI 執行日誌
└── flow/
    └── flow_XX.log      # 各 Flow 執行記錄
```

### 查看即時日誌

```powershell
# 查看最新日誌
Get-Content -Path logs/aiva_core/app.log -Wait -Tail 50
```

### 常見錯誤處理

| 錯誤類型 | 訊息 | 解決方案 |
|---------|------|---------|
| 模組未找到 | `ModuleNotFoundError` | 確認從專案根目錄執行，入口點已自動處理路徑 |
| 類別未找到 | `找不到類別 XXX` | 重新執行 Pipeline 更新數據 |
| 超時 | `TimeoutError` | 調低 concurrency 或增加 timeout |
| WAF 攔截 | `IP blocked` | 啟用 stealth 模式 |

## 6. 實戰範例

### 範例 1: 基本 Web 掃描

```batch
# Step 1: 執行掃描
python -m services.core.aiva_core.core_capabilities.cli.aiva_cli flow0 ^
  --target https://testphp.vulnweb.com ^
  --intensity 0.5

# Step 2: 查看結果
# 結果會輸出到終端機或指定的輸出路徑
```

### 範例 2: 安全模式掃描

```batch
# 使用低強度避免觸發 WAF
python -m services.core.aiva_core.core_capabilities.cli.aiva_cli flow0 ^
  --target https://example.com ^
  --intensity 0.2 ^
  --param mode=stealth ^
  --param delay=2000
```

### 範例 3: 批次執行多個 Flow

```powershell
# PowerShell 腳本
$flows = 0..5
$target = "https://example.com"

foreach ($id in $flows) {
    Write-Host "執行 Flow $id ..."
    python -m services.core.aiva_core.core_capabilities.cli.aiva_cli "flow$id" `
        --target $target `
        --intensity 0.5
    Start-Sleep -Seconds 2
}
```

### 範例 4: 條件執行

```powershell
# 只有成功才繼續
python -m services.core.aiva_core.core_capabilities.cli.aiva_cli flow0 --target URL
if ($LASTEXITCODE -eq 0) {
    Write-Host "Flow 0 成功，繼續 Flow 1"
    python -m services.core.aiva_core.core_capabilities.cli.aiva_cli flow1 --target URL
}
```

```
Step 7: 路徑解析
```
