## 1. 系統概述

### 什麼是數據流分析？

AIVA 的數據流分析系統是一個**自動化程式碼理解框架**，能夠：

- 🔍 **自動發現**模組間的調用關係
- 🔗 **追蹤數據流**在不同腳本之間的傳遞
- 📊 **分類整理**成可執行的流程鏈
- 🎯 **動態執行**任意流程進行測試

### 雙軌分析架構

```
┌─────────────────────────────────────────────────────────┐
│              AIVA 數據流分析系統                          │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  ┌──────────────────────┐   ┌──────────────────────┐   │
│  │   內部分析（內探）     │   │   外部分析（外攻）    │   │
│  │   Internal Analysis   │   │  External Analysis   │   │
│  ├──────────────────────┤   ├──────────────────────┤   │
│  │ 對象: AI Core        │   │ 對象: Features/Scan  │   │
│  │ 語言: Python Only    │   │ 語言: 4 Languages    │   │
│  │ 模組: 5 個           │   │ 模組: 14 個          │   │
│  │ 流程: 171 條         │   │ 流程: 525 條         │   │
│  └──────────────────────┘   └──────────────────────┘   │
│           │                           │                 │
│           ▼                           ▼                 │
│  internal_classification.json  external_classification.json │
│           │                           │                 │
│           └───────────┬───────────────┘                 │
│                       ▼                                 │
│            ┌─────────────────────┐                      │
│            │   統一執行器框架     │                      │
│            │  動態模組載入        │                      │
│            │  互動式選單          │                      │
│            └─────────────────────┘                      │
└─────────────────────────────────────────────────────────┘
```

### 內部 vs 外部的差異

| 維度 | 內部分析 | 外部分析 |
|------|---------|---------|
| **分析對象** | AIVA Core (AI 系統核心) | Features + Scan Engines |
| **語言支援** | Python only | Python, Go, Rust, TypeScript |
| **模組數量** | 5 個核心模組 | 14 個功能模組 (10 features + 4 engines) |
| **流程數量** | 171 條 | 525 條 |
| **分析工具** | Python AST | Python AST + Go/Rust/TS 編譯器 |
| **主要目的** | 理解 AI 決策流程 | 理解攻擊能力 |
| **典型流程** | task_executor → decision_maker → llm_client | SQLi detector → payload_generator → http_client |
| **數據位置** | `services/core/aiva_core/` | `services/features/`, `services/scan/` |

### 為什麼需要雙軌？

**內部分析**回答：
- AI 如何做決策？
- 數據如何在認知核心中流動？
- 任務規劃器如何調用能力？

**外部分析**回答：
- 系統有哪些攻擊能力？
- 每個能力的入口函數是什麼？
- 如何調用 Go/Rust 編寫的高性能引擎？

### 2.2 依賴注入模式

#### 為什麼需要依賴注入？

**問題背景**：
- ❌ **舊架構**：CommanderCoordinator 內部創建執行器 → 指揮鏈斷裂
- ✅ **新架構**：app.py 創建執行器並注入 → 指揮鏈完整

**核心優勢**：
1. **單一實例**：整個系統使用同一個執行器實例
2. **生命週期控制**：在 app.py 統一管理
3. **測試友好**：可以輕鬆注入 mock 執行器
4. **依賴透明**：一眼看出所有依賴關係

#### 依賴注入流程

```python
# ===== app.py - 啟動時創建並注入 =====
@app.on_event("startup")
async def startup():
    global coordinator, decision_agent, commander
    
    # 1. 創建執行器實例
    unified_executor = UnifiedAttackExecutor()
    multilang_coordinator = MultiEngineCoordinator()
    internal_loop = InternalLoopConnector()
    
    # 2. 創建 AI 決策引擎
    decision_agent = EnhancedDecisionAgent()
    
    # 3. 注入執行器到 CommanderCoordinator
    commander = CommanderCoordinator(
        unified_executor=unified_executor,
        multilang_coordinator=multilang_coordinator,
        internal_loop_connector=internal_loop
    )
    
    # 4. 創建協調器（使用 Commander）
    coordinator = AIVACoordinator(
        commander=commander,
        decision_agent=decision_agent
    )

# ===== CommanderCoordinator - 接收並傳遞依賴 =====
class CommanderCoordinator:
    def __init__(
        self,
        unified_executor: UnifiedAttackExecutor,
        multilang_coordinator: MultiEngineCoordinator,
        internal_loop_connector: InternalLoopConnector
    ):
        # 儲存注入的執行器
        self._unified_executor = unified_executor
        self._multilang_coordinator = multilang_coordinator
        self._internal_loop_connector = internal_loop_connector
        
        # 惰性加載的子模組（接收到請求時才創建）
        self._attack_coordinator = None
        self._plan_builder = None
        self._strategy_engine = None
    
    @property
    def attack_coordinator(self):
        """惰性加載：只在需要時創建，並傳遞執行器"""
        if self._attack_coordinator is None:
            self._attack_coordinator = AttackCoordinator(
                unified_executor=self._unified_executor,
                multilang_coordinator=self._multilang_coordinator,
                internal_loop=self._internal_loop_connector
            )
        return self._attack_coordinator

# ===== AttackCoordinator - 使用注入的執行器 =====
class AttackCoordinator:
    def __init__(
        self,
        unified_executor: UnifiedAttackExecutor,
        multilang_coordinator: MultiEngineCoordinator,
        internal_loop: InternalLoopConnector
    ):
        # 簡化參數：只接收 3 個核心依賴
        self.unified_executor = unified_executor
        self.multilang_coordinator = multilang_coordinator
        self.internal_loop = internal_loop
    
    async def coordinate_attack(self, target: str, attack_type: str):
        """使用注入的執行器執行攻擊"""
        # 使用統一執行器
        result = await self.unified_executor.execute(
            command=f"scan {target}",
            attack_type=attack_type
        )
        
        # 使用多語言協調器
        engine_result = await self.multilang_coordinator.execute(
            engine="python",
            task="analyze",
            data=result
        )
        
        return engine_result
```

### 3.4 核心設計原則

#### 原則 1: 只連接跨腳本調用

**為什麼？** 同一腳本內的函數調用是實現細節，不屬於數據流範疇。

```python
# ❌ 不追蹤：同腳本內的函數調用（實現細節）
# File: storage_manager.py
class StorageManager:
    def save(self, data):
        self._validate(data)  # 同腳本，不追蹤
        self._write(data)     # 同腳本，不追蹤

# ✅ 追蹤：跨腳本的函數調用（數據流）
# File: storage_manager.py
class StorageManager:
    def save(self, data):
        backend = SQLiteBackend()  # 來自 backends.py，追蹤！
        backend.write(data)
```

#### 原則 2: 不合併不同路徑

**為什麼？** 中間路徑不同會產生完全不同的結果。

```python
# 起點和終點相同，但中間路徑不同
Flow A: storage_manager → encryption_layer → backends  # 數據被加密
Flow B: storage_manager → compression_layer → backends # 數據被壓縮
Flow C: storage_manager → backends                     # 直接存儲

# ❌ 錯誤做法：合併為一個 "storage_manager → backends"
# ✅ 正確做法：保留三條獨立流程（因為處理邏輯完全不同）
```

**配置項**:

### 6.1 自動化測試覆蓋率

```python
# test_coverage_analyzer.py
import json
from pathlib import Path

def analyze_coverage():
    # 載入內部流程
    flows = json.loads(Path("internal_classification.json").read_text())
    
    # 載入測試文件
    test_files = Path("tests/").rglob("test_*.py")
    
    # 分析覆蓋率
    coverage = {}
    for flow in flows:
        entry_point = flow['start_function']
        has_test = any(entry_point in test.read_text() for test in test_files)
        coverage[entry_point] = has_test
    
    # 報告
    covered = sum(coverage.values())
    total = len(coverage)
    print(f"測試覆蓋率: {covered}/{total} ({covered/total*100:.1f}%)")
    
    # 未覆蓋的流程
    uncovered = [k for k, v in coverage.items() if not v]
    print(f"\n未覆蓋的關鍵流程 ({len(uncovered)}):")
    for func in uncovered[:10]:
        print(f"  - {func}")

if __name__ == "__main__":
    analyze_coverage()
```

def generate_mermaid(classification_file, output_file, module_filter=None):

```python
# rag_injector.py
from services.core.aiva_core.cognitive_core.rag import VectorStore

def inject_flows_to_rag():

            }
        )

if __name__ == "__main__":
```

### 6.5 性能監控

**追蹤流程執行時間**

```python
# flow_performance_monitor.py
import time
import json
from functools import wraps

class FlowPerformanceMonitor:
    def __init__(self):
        self.metrics = {}
    
    def monitor_flow(self, flow_id):
        def decorator(func):
            @wraps(func)
            def wrapper(*args, **kwargs):
                start = time.time()
                result = func(*args, **kwargs)
                duration = time.time() - start
                
                if flow_id not in self.metrics:
                    self.metrics[flow_id] = []
                self.metrics[flow_id].append(duration)
                
                return result
            return wrapper
        return decorator
    
    def report(self):
        for flow_id, durations in self.metrics.items():
            avg = sum(durations) / len(durations)
            print(f"Flow {flow_id}: 平均 {avg:.3f}s, 執行 {len(durations)} 次")

# 使用
monitor = FlowPerformanceMonitor()

@monitor.monitor_flow("flow_148")
def execute_sqli_fingerprint():
    # 執行流程...
```
