## 🎯 系統概述

**AIVA (AI-Driven Vulnerability Assessment)** 是一個企業級 Bug Bounty 平台，採用 AI 驅動的智能決策系統，專精於：

- ✅ **動態漏洞檢測** - 自動化黑盒滲透測試
- ✅ **智能攻擊策略** - AI 驅動的決策引擎
- ✅ **多語言協同** - Python/Rust/Go/TypeScript 引擎
- ✅ **Bug Bounty 優化** - 針對 HackerOne/Bugcrowd 實戰場景

### 核心特性

| 特性 | 說明 |
|------|------|
| 🧠 **AI 決策引擎** | 5M 參數神經網路 + RAG 向量檢索 |
| 🎯 **四大決策方法** | 掃描策略、Phase1/2 決策、結果評估 |
| 🔍 **多引擎掃描** | Python/Go/Rust/TypeScript 協同 |
| 📊 **企業級標準** | CVSS v3.1、MITRE ATT&CK、SARIF v2.1.0 |
| 🔄 **雙閉環學習** | 內閉環 (即時) + 外閉環 (經驗學習) |

## 🚪 程式入口點

AIVA 採用**雙層入口架構**，提供安全防護和 AI 系統分離：

### 1️⃣ main.py - 系統對外入口 (Port 9000)

**位置**: `services/core/main.py`  
**角色**: 第一道安全防線，整個程式的對外 HTTP 入口

**職責**:
- ✅ 檢測惡意請求（木馬、注入攻擊、異常參數）
- ✅ 速率限制和訪問控制
- ✅ 請求白名單/黑名單
- ✅ 保護 AI 系統不受污染

**啟動方式**:
```bash
cd services/core
python main.py
# 服務運行在 http://0.0.0.0:9000
```

**API 端點**:
- `GET /health` - 健康檢查
- `POST /scan` - 創建掃描任務
- `GET /status/{scan_id}` - 查詢掃描狀態

---

### 2️⃣ app.py - AI 系統入口 (Port 8000)

**位置**: `services/core/aiva_core/service_backbone/api/app.py`  
**角色**: 程式與 AI 的溝通接口（AI 可插拔）

**職責**:
- ✅ 接收來自 main.py 的請求
- ✅ 調用 AI 決策引擎
- ✅ 協調任務規劃與執行
- ✅ 雙路分離處理（實時記錄 + AI 決策）

**數據流**:
```
外部 HTTP 請求
    ↓
main.py (Port 9000) - 安全檢測
    ↓ 通過檢測後轉發
app.py (Port 8000) - AI 系統入口
    ↓
雙路分離處理:
  ├─ 路徑1: integration 模組存儲（實時記錄）
  └─ 路徑2: AI 內部 → 任務規劃 → 執行模組
```

## 📦 安裝與部署

### 方式一：開發環境安裝

```bash
# 1. 克隆專案
git clone https://github.com/your-org/AIVA-git.git
cd AIVA-git

# 2. 安裝 Python 依賴
cd services/core
pip install -r requirements.txt

# 3. 安裝 aiva_common（共享庫）
cd ../aiva_common
pip install -e .

# 4. 配置環境變數（可選）
cp .env.example .env
# 編輯 .env 設定數據庫連接等

# 5. 初始化數據庫（如使用 PostgreSQL）
cd ../integration
alembic upgrade head

# 6. 啟動服務
cd ../core
python main.py  # Port 9000
```

### 方式二：Docker 部署（推薦）

```bash
# 1. 使用 Docker Compose 啟動所有服務
docker-compose up -d

# 2. 驗證服務狀態
docker-compose ps

# 3. 查看日誌
docker-compose logs -f aiva-core
```

```bash

  "vulnerabilities_found": 3,
  "estimated_remaining_time": 120
}
```

### 4. 停止掃描任務

```bash
# 停止指定掃描
curl -X DELETE http://localhost:9000/scan/{scan_id}
```

## 📝 附錄

### A. 常見問題 (FAQ)

**Q1: 為什麼需要兩個入口點（main.py 和 app.py）？**

A: 這是安全設計。`main.py` 作為第一道防線，過濾惡意請求後才轉發給 `app.py`（AI 系統），避免 AI 系統受到污染或攻擊。

**Q2: 可以只啟動 app.py 嗎？**

A: 可以，但不建議。生產環境應該使用 `main.py` 作為對外入口，確保安全性。開發測試時可以直接訪問 `app.py` (Port 8000)。

**Q3: 如何查看詳細日誌？**

A: 日誌位於 `logs/` 目錄，或使用 `docker-compose logs -f` 查看即時日誌。

**Q4: 系統支援哪些掃描類型？**

A: 支援 `quick`（快速掃描）、`full`（完整掃描）、`deep`（深度掃描）、`custom`（自定義掃描）。
