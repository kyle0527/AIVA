## ⚠️ 重要公告

**AIVA v2.0 對策略系統進行了重大更新**：

### 已移除的功能

| 舊功能 | 說明 | 替代方案 |
|--------|------|----------|
| `AIVA_ENV` 環境變數 | sandbox/production 模式 | 使用 `target_sensitivity` |
| `scan_type` 參數 | "aggressive"/"balanced"/"stealth" | 使用 4 維度策略系統 |
| `mode` 參數 | 攻擊模式選擇 | 自動根據 `target_sensitivity` 決定 |
| 環境類型區分 | 訓練環境 vs 生產環境 | 統一使用目標敏感度 |

### 新增的功能

| 新功能 | 說明 |
|--------|------|
| `target_sensitivity` | 目標敏感度（0.0-1.0）|
| 4 維度策略模型 | intensity, stealth, coverage, persistence |
| 自動策略選擇 | AI 根據敏感度智能選擇策略 |

---

## 1. 重大變更說明

### 1.1 為什麼要改變？

**舊系統的問題**：
```
❌ sandbox/production 二元分類太簡單
❌ "aggressive"/"stealth" 等模式不夠精確
❌ 無法反映真實世界的目標差異性
❌ 訓練和生產環境強制分離不靈活
```

**新系統的優勢**：
```
✅ 目標敏感度可精確控制（0.0-1.0）
✅ 4 維度策略模型更貼近實戰需求
✅ AI 自動根據敏感度選擇最佳策略
✅ 同一系統可處理各種敏感度目標
```

### 1.2 概念對比

| 概念 | 舊系統 | 新系統 |
|------|--------|--------|
| **環境區分** | sandbox / production | 無環境概念 |
| **目標分類** | 模式選擇（3種） | 敏感度連續值（無限） |
| **策略選擇** | 用戶手動指定 | AI 自動選擇 |
| **參數名稱** | `AIVA_ENV`, `scan_type`, `mode` | `target_sensitivity` |

## 2. 新策略系統概覽

### 2.1 目標敏感度（Target Sensitivity）

目標敏感度是一個 **0.0 到 1.0 的連續值**，表示目標的重要性和風險承受度：

```
0.0 ───────── 0.3 ───────── 0.5 ───────── 0.7 ───────── 1.0
低敏感度      中低敏感度     中等敏感度     中高敏感度     高敏感度
(測試環境)    (開發環境)    (預生產)      (生產環境)    (核心系統)
```

**敏感度值含義**：

| 範圍 | 分類 | 典型場景 | 推薦策略 |
|------|------|----------|----------|
| 0.0 - 0.3 | 低敏感度 | 測試靶場、本地開發環境 | 高強度、全覆蓋 |
| 0.3 - 0.5 | 中低敏感度 | 開發環境、內部測試 | 中等強度 |
| 0.5 - 0.7 | 中等敏感度 | 預生產環境、UAT | 平衡策略 |
| 0.7 - 0.9 | 中高敏感度 | 生產環境、客戶系統 | 隱蔽掃描 |
| 0.9 - 1.0 | 高敏感度 | 核心業務系統、金融系統 | 極度謹慎 |

### 2.2 四維度策略模型

新系統使用 **4 個維度** 來精確定義攻擊策略：

#### 1️⃣ **Intensity（強度）** - 攻擊的激烈程度
```
0.0 ─────────────── 0.5 ─────────────── 1.0
極輕量級             中等強度            極高強度
(單線程，慢速)        (並發度中等)         (高並發，快速)
```

**示例**：
- 低敏感度目標 (0.2) → Intensity: 0.9（高並發掃描）
- 高敏感度目標 (0.8) → Intensity: 0.2（單線程，慢速）

#### 2️⃣ **Stealth（隱蔽性）** - 避免被檢測的程度
```
0.0 ─────────────── 0.5 ─────────────── 1.0
完全公開             適度隱蔽            極度隱蔽
(標準 UA)           (偽裝瀏覽器)         (完全模擬真人)
```

**示例**：
- 低敏感度目標 (0.2) → Stealth: 0.2（不隱藏）
- 高敏感度目標 (0.8) → Stealth: 0.9（極度隱蔽）

#### 3️⃣ **Coverage（覆蓋率）** - 測試範圍的廣度
```
0.0 ─────────────── 0.5 ─────────────── 1.0
極窄範圍             中等範圍            全面覆蓋
(關鍵端點)           (常見漏洞)          (所有可能點)
```

**示例**：
- 低敏感度目標 (0.2) → Coverage: 0.95（全面測試）
- 高敏感度目標 (0.8) → Coverage: 0.4（僅關鍵點）

#### 4️⃣ **Persistence（持久性）** - 遇到阻礙時的堅持程度
```
0.0 ─────────────── 0.5 ─────────────── 1.0
快速放棄             適度重試            堅持到底
(失敗即停)           (重試 2-3 次)       (繞過所有障礙)
```

**示例**：
- 低敏感度目標 (0.2) → Persistence: 0.9（持續嘗試）
- 高敏感度目標 (0.8) → Persistence: 0.3（謹慎重試）

### 2.3 策略自動映射

**系統會自動根據 target_sensitivity 計算 4 個維度**：

```python
# 低敏感度（0.2）- 測試環境
target_sensitivity = 0.2
↓
{
    "intensity": 0.9,      # 高強度
    "stealth": 0.2,        # 低隱蔽
    "coverage": 0.95,      # 全覆蓋
    "persistence": 0.9     # 高持久
}

# 高敏感度（0.8）- 生產環境
target_sensitivity = 0.8
↓
{
    "intensity": 0.2,      # 低強度
    "stealth": 0.9,        # 高隱蔽
    "coverage": 0.4,       # 窄範圍
    "persistence": 0.3     # 低持久
}
```

## 3. 目標敏感度使用指南

### 3.1 如何設置目標敏感度？

#### 方法 1：HTTP API（推薦）

```powershell
# 低敏感度（測試環境）
curl -X POST http://localhost:8000/scan `
  -H "Content-Type: application/json" `
  -d '{
    "target": "https://test.example.com",
    "target_sensitivity": 0.2
  }'

# 高敏感度（生產環境）
curl -X POST http://localhost:8000/scan `
  -H "Content-Type: application/json" `
  -d '{
    "target": "https://production.example.com",
    "target_sensitivity": 0.8
  }'
```

#### 方法 2：環境變數（可選）

```powershell
# Windows PowerShell
$env:AIVA_TARGET_SENSITIVITY = "0.5"
python services/core/aiva_core/service_backbone/api/app.py

# Linux/Mac
export AIVA_TARGET_SENSITIVITY=0.5
python services/core/aiva_core/service_backbone/api/app.py
```

#### 方法 3：配置文件（未來版本）

```yaml
# config/settings.yaml
default_target_sensitivity: 0.5

target_profiles:
  test_environment:
    sensitivity: 0.2
  production:
    sensitivity: 0.8
```

### 3.2 如何選擇合適的敏感度值？

**決策樹**：

```
1. 這是測試/靶場環境嗎？
   ├─ 是 → sensitivity = 0.1 - 0.3
   └─ 否 → 繼續

2. 目標是生產環境嗎？
   ├─ 是 → 繼續
   └─ 否（開發/預生產）→ sensitivity = 0.4 - 0.6

3. 是核心業務系統嗎？
   ├─ 是（支付/用戶數據/金融）→ sensitivity = 0.8 - 1.0
   └─ 否（一般業務）→ sensitivity = 0.6 - 0.8
```

**實際案例**：

| 目標類型 | 敏感度 | 理由 |
|---------|--------|------|
| HackTheBox / TryHackMe | 0.1 | 專門的訓練靶場 |
| 本地 Docker 測試環境 | 0.2 | 本地測試，無風險 |
| 公司內部開發環境 | 0.4 | 內網，影響有限 |
| UAT/預生產環境 | 0.6 | 接近生產，需謹慎 |
| Bug Bounty 目標 | 0.7 | 真實生產，有監控 |
| 客戶生產環境 | 0.8 | 高風險，需極度謹慎 |
| 銀行/支付系統 | 0.9 | 核心業務，不容閃失 |

## 4. 遷移指南

### 4.1 從舊 API 遷移

#### 舊代碼（AIVA v1.x）

```powershell
# ❌ 舊方式 - 不再支持
curl -X POST http://localhost:8000/scan `
  -d '{
    "target": "https://example.com",
    "scan_type": "aggressive",
    "mode": "stealth"
  }'
```

#### 新代碼（AIVA v2.0+）

```powershell
# ✅ 新方式 - 使用 target_sensitivity
curl -X POST http://localhost:8000/scan `
  -d '{
    "target": "https://example.com",
    "target_sensitivity": 0.3
  }'
```

### 4.2 參數映射表

如果您之前使用舊參數，可以參考此表進行轉換：

| 舊參數組合 | 建議的 target_sensitivity |
|-----------|--------------------------|
| `scan_type: "stealth"` + sandbox | 0.2 - 0.3 |
| `scan_type: "balanced"` + sandbox | 0.3 - 0.4 |
| `scan_type: "aggressive"` + sandbox | 0.1 - 0.2 |
| `scan_type: "stealth"` + production | 0.7 - 0.9 |
| `scan_type: "balanced"` + production | 0.5 - 0.7 |
| `scan_type: "aggressive"` + production | 不建議（使用 0.4 - 0.5） |

### 4.3 環境變數遷移

```powershell
# ❌ 舊方式
$env:AIVA_ENV = "production"

# ✅ 新方式
$env:AIVA_TARGET_SENSITIVITY = "0.7"
```

## 5. 常見問題

### Q1: 我還能使用 `scan_type` 參數嗎？

**A**: 不能。AIVA v2.0+ 已完全移除 `scan_type` 參數。系統會忽略該參數並返回警告。請改用 `target_sensitivity`。

### Q2: 如果我不指定 `target_sensitivity`，會發生什麼？

**A**: 系統會使用默認值 **0.5**（中等敏感度），這對大多數場景是合理的平衡。

### Q3: 能否在掃描過程中動態調整敏感度？

**A**: 目前不支持。敏感度在掃描開始時設定，並在整個掃描過程中保持不變。未來版本可能支持動態調整。

### Q4: 舊版 AIVA 的配置文件還能用嗎？

**A**: 如果配置文件中包含 `AIVA_ENV` 或 `scan_type`，系統會發出警告並忽略這些設置。建議更新配置文件使用新參數。

### Q5: 訓練模式和生產模式的差異如何體現？

**A**: 不再有明確的"訓練/生產"區分。您可以通過設置不同的 `target_sensitivity` 來達到相同效果：
- 訓練/測試：sensitivity = 0.1 - 0.3
- 生產環境：sensitivity = 0.6 - 0.9

### Q6: 我可以直接指定 4 個維度值嗎？

**A**: 目前不支持。系統會根據 `target_sensitivity` 自動計算 4 個維度。未來版本可能允許高級用戶手動覆蓋。

### Q7: 如何查看當前使用的策略？

**A**: 查看掃描日誌或 API 響應：

```json
{
  "scan_id": "scan_abc123",
  "target_sensitivity": 0.7,
  "strategy": {
    "intensity": 0.3,
    "stealth": 0.8,
    "coverage": 0.5,
    "persistence": 0.4
  }
}
```
