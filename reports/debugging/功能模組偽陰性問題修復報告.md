## 📊 問題總覽

根據深度代碼審查和 Refactor Plan 分析,AIVA 功能模組存在**嚴重的偽陰性問題**:

### 🚨 核心問題

**偽陰性 (False Negative)**: 系統在工具執行失敗時回傳"成功但無漏洞",而非報錯

```python
# ❌ 危險模式: 工具失敗 → 回傳"掃描完成,無漏洞"
try:
    result = execute_xss_tool(target)
except Exception:
    return XSSResult(
        success=True,  # ❌ 回傳成功
        vulnerabilities=[],  # ❌ 空漏洞列表
        note="(Simulated)"  # ❌ 僅有註記
    )

# ✅ 正確模式: 工具失敗 → 拋出異常
try:
    result = execute_xss_tool(target)
except Exception as e:
    raise RuntimeError(f"XSS 工具執行失敗: {e}") from e
```

**影響**: 用戶誤以為目標安全,實際上根本沒有掃描

### 1. XSS 檢測模組 ❌

**文件**: `services/features/function_xss/engines/hackingtool_engine.py`

**問題位置**: 第 300-350 行 (推測,需確認)

**偽陰性場景**:
```python
# ❌ 當前邏輯 (推測)
async def _execute_tool_detection(self, plan, target_url):
    try:
        # 執行 xsser/xsstrike 等工具
        tool_config = self.config.get_tool_config(tool_name)
        if not tool_config:
            # 工具未配置,但回傳空結果而非報錯
            return XSSDetectionResult(
                tool_name=tool_name,
                vulnerability_found=False,  # ❌ 
                payloads=[],
                raw_output="(Simulated)"  # ❌
            )
        
        result = await self._execute_go_tool(tool_config, target_url)
        return result
        
    except Exception as e:
        self.logger.error(f"Tool failed: {e}")
        # ❌ 捕捉異常後回傳空結果
        return None  # 或空的 XSSDetectionResult
```

**修復要求**:
1. ✅ 移除所有 `(Simulated)` 標記
2. ✅ 工具未安裝 → 拋出 `RuntimeError`
3. ✅ 工具執行失敗 → 拋出異常,不捕捉
4. ✅ 啟動時檢查工具路徑 (`initialize()` 方法)

### 2. SQL 注入檢測模組 ❌

**文件**: `services/features/function_sqli/engines/hackingtool_engine.py`

**問題位置**: 第 150-170 行

**實際代碼問題**:
```python
# ❌ 當前邏輯
async def _execute_tool(self, tool_name: str, target: str):
    try:
        # 執行 sqlmap
        process = await asyncio.create_subprocess_shell(cmd, ...)
        stdout, stderr = await asyncio.wait_for(
            process.communicate(), timeout=config.timeout_seconds
        )
    except asyncio.TimeoutError:
        # ❌ 超時回傳"失敗",但不拋出異常
        return {"success": False, "error": "timeout"}
    except Exception as e:
        # ❌ 異常回傳"失敗",但不拋出
        return {"success": False, "error": str(e)}

# 調用端處理
result = await self._execute_tool(tool_name, target)
if not result.get("success"):
    # ❌ 僅記錄警告,繼續執行
    logger.warning(f"Tool {tool_name} 執行失敗")
    return []  # ❌ 回傳空列表,上層以為掃描完成
```

**修復要求**:
1. ✅ `_execute_tool()` 失敗時拋出異常
2. ✅ 移除 `{"success": False}` 字典回傳
3. ✅ sqlmap 未安裝 → `initialize()` 時檢查並報錯
4. ✅ 指紋識別失敗 → 拋出異常

## ✅ 修復原則

### 1. Fail Fast 原則

```python
# ❌ 錯誤: 靜默失敗
try:
    result = tool.execute()
except Exception:
    return []  # 回傳空結果

# ✅ 正確: 快速失敗
result = tool.execute()  # 讓異常向上傳播
```

### 2. 初始化時檢查

```python
class XSSEngine:
    async def initialize(self) -> bool:
        """初始化時檢查所有依賴"""
        # ✅ 檢查工具可用性
        if not shutil.which("xsser"):
            raise RuntimeError(
                "XSS 工具未安裝: xsser not found in PATH. "
                "請安裝: pip install xsser"
            )
        
        # ✅ 檢查工具版本
        result = await self._run_command(["xsser", "--version"])
        if result.returncode != 0:
            raise RuntimeError("xsser 無法執行")
        
        return True
```

### 3. 明確的錯誤消息

```python
# ✅ 提供安裝指南
raise RuntimeError(
    "SQLMap 未安裝或配置錯誤\n"
    "安裝方法:\n"
    "  - apt-get install sqlmap (Debian/Ubuntu)\n"
    "  - brew install sqlmap (macOS)\n"
    "  - https://github.com/sqlmapproject/sqlmap\n"
    f"當前 PATH: {os.environ.get('PATH')}"
)
```

## 📝 結論

AIVA 功能模組的核心問題不是代碼缺失或使用 Mock,而是**錯誤處理邏輯缺陷**:

**問題本質**: 為了保持系統"流暢運行",在工具執行失敗時選擇靜默降級

**修復核心**: 遵循 Fail Fast 原則,讓錯誤快速暴露

**預期效果**: 
- ✅ 提高系統可信度
- ✅ 避免偽陰性風險
- ✅ 明確告知用戶依賴問題
