## 資料備份與恢復

### 自動備份機制

整合模組提供自動備份功能，定期備份所有關鍵資料。

#### 備份策略

| 資料類型 | 備份頻率 | 保留期限 | 儲存位置 |
|---------|---------|---------|---------|
| 攻擊路徑圖 | 每日 | 7 天 | `data/integration/backups/attack_paths/` |
| 經驗資料庫 | 每日 | 30 天 | `data/integration/backups/experiences/` |
| 訓練資料集 | 每週 | 90 天 | `data/integration/backups/training_datasets/` |

#### 手動備份

##### 方式 1: 使用備份腳本

```bash
# 完整備份（所有資料）
python services/integration/scripts/backup.py

# 僅備份攻擊路徑圖
python services/integration/scripts/backup.py --attack-graph-only

# 僅備份經驗資料庫
python services/integration/scripts/backup.py --experience-only

# 僅備份訓練資料集
python services/integration/scripts/backup.py --training-dataset-only
```

**備份輸出**:
```
✅ 備份完成
  - 攻擊路徑圖: data/integration/backups/attack_paths/attack_graph_20251124_143025.pkl
  - 經驗資料庫: data/integration/backups/experiences/experience_20251124_143025.db
  - 訓練資料集: data/integration/backups/training_datasets/datasets_20251124_143025.tar.gz
```

##### 方式 2: 使用 API

```python

    get_unified_data_manager,
)

manager = get_unified_data_manager()

# 保存攻擊圖（自動創建備份）
manager.save_attack_graph()
print("✅ 攻擊路徑圖已備份")
```


```powershell

$trigger = New-ScheduledTaskTrigger -Daily -At 2am
Register-ScheduledTask -Action $action -Trigger $trigger -TaskName "AIVA_Daily_Backup"
```

### 資料庫維護

#### PostgreSQL 維護

```sql
-- 1. 分析表統計
ANALYZE findings;

-- 2. 清理死行
VACUUM FULL findings;

-- 3. 重建索引
REINDEX TABLE findings;

-- 4. 檢查表大小
SELECT 
    pg_size_pretty(pg_total_relation_size('findings')) as total_size,
    pg_size_pretty(pg_relation_size('findings')) as table_size,
```

## 性能優化建議

### 查詢優化

#### 1. 使用分頁

**❌ 不好**: 一次查詢大量資料
```python
# 避免這樣做
findings = manager.query_findings(limit=100000)  # 太多
```

**✅ 好**: 使用分頁
```python
page_size = 100
for page in range(10):
    findings = manager.query_findings(
        limit=page_size,
        offset=page * page_size,
    )
    process_findings(findings)
```

#### 2. 使用過濾器

**❌ 不好**: 查詢所有再過濾
```python
# 避免這樣做
all_findings = manager.query_findings()
critical_findings = [f for f in all_findings if f['severity'] == 'CRITICAL']
```

**✅ 好**: 使用資料庫過濾
```python
critical_findings = manager.query_findings(severity=Severity.CRITICAL)
```

#### 3. 限制返回數量

```python
# 只取需要的數量
top_experiences = manager.query_high_quality_experiences(
    min_score=0.9,
    limit=10,  # 只要前 10 個
)
```

### 批次操作

#### 批次保存漏洞

```python
from services.aiva_common.schemas import FindingPayload

findings = [finding1, finding2, finding3, ...]  # 大量漏洞

# 批次保存
for finding in findings:
    manager.save_finding(finding, scan_id="scan_001")

# 或使用事務（更高效）
from services.integration.aiva_integration.finding_repository import FindingRepository

repo = FindingRepository()
with repo.session_scope() as session:
    for finding in findings:
        repo.save(finding, scan_id="scan_001", session=session)
```

### 資料庫連接池

UnifiedDataManager 自動使用連接池，無需手動管理：

```python
# 連接池配置 (在 config.py 中)
DATABASE_URL = "postgresql://user:pass@localhost:5432/db?pool_size=10&max_overflow=20"
```

**連接池參數**:
- `pool_size`: 連接池大小（預設 10）
- `max_overflow`: 最大溢出連接數（預設 20）

### 索引優化

確保 PostgreSQL 表有適當的索引：

```sql
-- 檢查現有索引
SELECT indexname, indexdef 
FROM pg_indexes 
WHERE tablename = 'findings';

-- 如果缺少索引，創建它們
CREATE INDEX IF NOT EXISTS idx_finding_id ON findings(finding_id);
CREATE INDEX IF NOT EXISTS idx_scan_id ON findings(scan_id);
CREATE INDEX IF NOT EXISTS idx_severity ON findings(severity);
CREATE INDEX IF NOT EXISTS idx_status ON findings(status);
CREATE INDEX IF NOT EXISTS idx_created_at ON findings(created_at);
```

## 故障排除

### 常見問題

#### 問題 1: PostgreSQL 連接失敗

**錯誤訊息**:
```
ERROR: could not connect to server: Connection refused
    Is the server running on host "localhost" and accepting TCP/IP connections on port 5432?
```

**診斷步驟**:
```bash
# 1. 檢查 PostgreSQL 是否運行
docker ps | grep postgres
# 或
systemctl status postgresql

# 2. 檢查連接字串
echo $DATABASE_URL
# 應為: postgresql://user:pass@host:5432/db_name

# 3. 測試連接
psql $DATABASE_URL -c "SELECT 1"
```

**解決方案**:
```bash
# 啟動 PostgreSQL
docker-compose up -d postgres
# 或
systemctl start postgresql

# 檢查防火牆
sudo ufw allow 5432/tcp
```

---

#### 問題 2: SQLite 資料庫鎖定

**錯誤訊息**:
```
sqlite3.OperationalError: database is locked
```

**診斷步驟**:
```bash
# 檢查是否有其他進程正在使用資料庫
lsof data/integration/experiences/experience.db
```

**解決方案**:
```python
# 1. 使用 WAL 模式（Write-Ahead Logging）
import sqlite3

conn = sqlite3.connect("experience.db")
conn.execute("PRAGMA journal_mode=WAL")
conn.close()

# 2. 設定 timeout
conn = sqlite3.connect("experience.db", timeout=30.0)
```

#### 問題 4: 記憶體使用過高

**症狀**: 查詢大量資料時記憶體激增

**診斷**:
```python
import tracemalloc

tracemalloc.start()

# 執行查詢
findings = manager.query_findings(limit=100000)

current, peak = tracemalloc.get_traced_memory()
print(f"當前記憶體: {current / 1024 / 1024:.2f} MB")
print(f"峰值記憶體: {peak / 1024 / 1024:.2f} MB")

tracemalloc.stop()
```

**解決方案**:
```python
# 使用分頁和生成器
def query_findings_generator(manager, page_size=100):
    offset = 0
    while True:
        findings = manager.query_findings(limit=page_size, offset=offset)
        if not findings:
            break
        yield from findings
        offset += page_size

# 使用
for finding in query_findings_generator(manager):
    process_finding(finding)  # 逐個處理，避免記憶體激增
```

## 監控與日誌

### 日誌配置

#### 基本日誌配置

```python
import logging
from logging.handlers import RotatingFileHandler

# 創建日誌目錄
log_dir = Path("logs/integration")
log_dir.mkdir(parents=True, exist_ok=True)

# 配置日誌
logger = logging.getLogger("aiva_integration")
logger.setLevel(logging.INFO)

# 文件處理器（自動輪轉）
file_handler = RotatingFileHandler(
    log_dir / "integration.log",
    maxBytes=10 * 1024 * 1024,  # 10 MB
    backupCount=5,               # 保留 5 個備份
)
file_handler.setFormatter(
    logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
)

# 控制台處理器
console_handler = logging.StreamHandler()
console_handler.setFormatter(
    logging.Formatter('%(levelname)s - %(message)s')
)

logger.addHandler(file_handler)
logger.addHandler(console_handler)
```

```python
def monitor_database_size():
```

### 健康檢查

```python
def health_check():
    """整合模組健康檢查"""
    
    checks = {
        "postgres": False,
        "sqlite": False,
        "attack_graph": False,
    }
    
    try:
        manager = get_unified_data_manager()
        
        # 檢查 PostgreSQL
        try:
            manager.query_findings(limit=1)
            checks["postgres"] = True
        except Exception as e:
            print(f"PostgreSQL 檢查失敗: {e}")
        
        # 檢查 SQLite
        try:
            manager.query_high_quality_experiences(limit=1)
            checks["sqlite"] = True
        except Exception as e:
            print(f"SQLite 檢查失敗: {e}")
        
        # 檢查攻擊圖
        try:
            manager.get_attack_graph_statistics()
            checks["attack_graph"] = True
        except Exception as e:
            print(f"Attack Graph 檢查失敗: {e}")
    
    except Exception as e:
        print(f"初始化失敗: {e}")
    
    # 返回健康狀態
    all_healthy = all(checks.values())
    status = "✅ 健康" if all_healthy else "❌ 異常"
    
    print(f"\n整合模組健康狀態: {status}")
    for check, result in checks.items():
        print(f"  {check}: {'✓' if result else '✗'}")
    
    return all_healthy
```
