## 統一資料管理器 (UnifiedDataManager)

### 設計原則

1. **單一入口點**: 所有資料訪問都通過 UnifiedDataManager
2. **多資料源支援**: PostgreSQL + SQLite + NetworkX
3. **自動化**: 自動持久化、備份、清理
4. **類型安全**: 使用 aiva_common schemas 和 enums
5. **易於使用**: 簡潔的 API 設計

### 核心組件

```python
class UnifiedDataManager:
    """統一資料管理器
    
    組件:
        - ExperienceRepository: 經驗記錄資料庫
        - FindingRepository: 漏洞發現資料庫
        - AttackPathEngine: 攻擊路徑圖引擎
    """
    
    def __init__(
        self,
        postgres_url: str = DATABASE_URL,
        experience_db_url: str = EXPERIENCE_DB_URL,
        attack_graph_file: Path | str = ATTACK_GRAPH_FILE,
    ):
        # 初始化三大資料源
        self.experience_repo = ExperienceRepository(experience_db_url)
        self.finding_repo = FindingRepository(postgres_url)
        self.attack_path_engine = AttackPathEngine(attack_graph_file)
```

### 主要功能分類

| 功能類別 | 方法數量 | 用途 |
|---------|---------|------|
| **經驗管理** | 3 | 保存、查詢、統計經驗記錄 |
| **漏洞管理** | 4 | 保存、查詢、更新、統計漏洞 |
| **攻擊路徑** | 4 | 管理資產、漏洞、路徑分析 |
| **統計查詢** | 3 | 獲取各類統計資訊 |
| **資料維護** | 2 | 備份、清理舊資料 |

### 使用模式

#### 模式 1: 單例模式 (推薦)

```python

    get_unified_data_manager,
)

# 獲取全域單例
manager = get_unified_data_manager()

# 在任何地方使用

```

**優點**: 
- 避免重複初始化
- 共享資料庫連接池
- 確保資料一致性

## 資料儲存架構

### 三大資料源

#### 1. PostgreSQL - 漏洞發現資料庫

**用途**: 儲存漏洞發現記錄

**表結構**: `findings` 表

| 欄位 | 類型 | 說明 | 索引 |
|------|------|------|------|
| id | SERIAL | 主鍵 | 主鍵 |
| finding_id | VARCHAR(255) | 漏洞唯一ID | ✓ |
| scan_id | VARCHAR(255) | 掃描ID | ✓ |
| vulnerability_name | VARCHAR(255) | 漏洞名稱 | - |
| severity | VARCHAR(50) | 嚴重性 (CRITICAL/HIGH/MEDIUM/LOW) | ✓ |
| confidence | VARCHAR(50) | 信心度 | - |
| target_url | TEXT | 目標URL | - |
| status | VARCHAR(50) | 狀態 (active/fixed/false_positive) | ✓ |
| created_at | TIMESTAMP | 創建時間 | ✓ |
| raw_data | JSONB | 原始資料 (JSON) | - |

**索引策略**:
- `idx_finding_id`: 快速查詢單個漏洞
- `idx_scan_id`: 按掃描查詢
- `idx_severity`: 按嚴重性過濾
- `idx_status`: 按狀態過濾
- `idx_created_at`: 時間範圍查詢

**查詢性能**:
```python
# 優化後的查詢 (使用索引)
findings = manager.query_findings(
    scan_id="scan_001",      # 使用 idx_scan_id
    severity=Severity.HIGH,  # 使用 idx_severity
    status="active",         # 使用 idx_status
)
```

#### 2. SQLite - 經驗記錄資料庫

**用途**: 儲存攻擊執行經驗，用於 AI 學習

**主要表結構**:

**表 1: experience_records** (核心表)

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | INTEGER | 主鍵 |
| experience_id | TEXT | 經驗唯一ID (UUID) |
| plan_id | TEXT | 執行計畫ID |
| attack_type | TEXT | 攻擊類型 (sqli, xss, idor, etc.) |
| ast_graph | TEXT | AST 圖結構 (JSON) |
| execution_trace | TEXT | 執行軌跡 (JSON) |
| metrics | TEXT | 評估指標 (JSON) |
| overall_score | REAL | 綜合分數 (0.0-1.0) |
| target_info | TEXT | 目標資訊 (JSON, 可選) |
| metadata | TEXT | 額外元數據 (JSON, 可選) |
| created_at | TIMESTAMP | 創建時間 |

**表 2: training_datasets** (資料集管理)

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | INTEGER | 主鍵 |
| dataset_id | TEXT | 資料集ID |
| attack_type | TEXT | 攻擊類型 |
| sample_count | INTEGER | 樣本數量 |
| export_path | TEXT | 導出路徑 |
| created_at | TIMESTAMP | 創建時間 |

**表 3: dataset_samples** (關聯表)

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | INTEGER | 主鍵 |
| dataset_id | TEXT | 資料集ID (外鍵) |
| experience_id | TEXT | 經驗ID (外鍵) |

**表 4: model_training_history** (訓練歷史)

| 欄位 | 類型 | 說明 |
|------|------|------|
| id | INTEGER | 主鍵 |
| training_id | TEXT | 訓練ID |
| dataset_id | TEXT | 使用的資料集ID |
| model_type | TEXT | 模型類型 |
| training_metrics | TEXT | 訓練指標 (JSON) |
| checkpoint_path | TEXT | 模型檢查點路徑 |
| created_at | TIMESTAMP | 訓練時間 |

**資料流程**:
```
攻擊執行 → save_attack_experience()
           ↓
     experience_records (儲存)
           ↓
query_high_quality_experiences() (過濾高分)
           ↓
     export_training_dataset() (導出)
           ↓
     training_datasets + dataset_samples
           ↓
     模型訓練 (外部)
           ↓
     model_training_history (記錄)
```

#### 3. NetworkX - 攻擊路徑圖

**用途**: 儲存資產與漏洞的攻擊路徑圖

**圖結構**:
- **類型**: NetworkX DiGraph (有向圖)
- **持久化**: pickle 格式
- **節點類型**: Asset (資產)、Vulnerability (漏洞)
- **邊類型**: Attack Path (攻擊路徑)

**節點屬性**:

**資產節點**:
```python
{
    "node_type": "asset",           # 節點類型
    "asset_id": "web_app_001",      # 資產ID
    "asset_type": "web_application", # 資產類型
    "url": "https://example.com",   # URL
    "metadata": {                    # 額外資訊
        "framework": "Django",
        "version": "3.2",
        "ports": [80, 443],
    }
}
```

**漏洞節點**:
```python
{
    "node_type": "vulnerability",   # 節點類型
    "vuln_id": "sqli_001",          # 漏洞ID
    "vuln_type": "sql_injection",   # 漏洞類型
    "severity": "critical",         # 嚴重性
    "affected_asset": "web_app_001", # 受影響資產
    "metadata": {                    # 額外資訊
        "cwe": "CWE-89",
        "cvss_score": 9.8,
    }
}
```

**邊屬性**:
```python
{
    "relationship": "exploits",      # 關係類型
    "attack_vector": "remote",       # 攻擊向量
    "complexity": "low",             # 複雜度
    "privilege_required": "none",    # 所需權限
}
```

**圖操作**:
```python
# 添加資產
manager.add_asset_to_attack_graph(
    asset_id="web_app_001",
    asset_type="web_application",
    url="https://example.com",
)

# 添加漏洞（自動創建邊）
manager.add_vulnerability_to_attack_graph(
    vuln_id="sqli_001",
    vuln_type="sql_injection",
    severity="critical",
    affected_asset="web_app_001",  # 自動建立 asset → vuln 的邊
)

# 查詢攻擊路徑
paths = manager.get_attack_paths_for_target(
    target="https://example.com/admin",
    max_paths=5,
)

# 保存圖（持久化）
manager.save_attack_graph()
```

## 資訊接收機制

### 接收來源模組

整合模組從以下模組接收資料：

#### 來源 1: Core 模組

**發送方**: `AICommander`, `AttackExecutor`, `RAGEngine`

| 資訊類型 | 接口方法 | 觸發時機 | 資料格式 |
|---------|---------|---------|---------|
| 攻擊執行經驗 | `save_attack_experience()` | 每次攻擊完成後 | ExperienceRecord |
| AST 圖結構 | (包含在經驗中) | 計畫生成時 | Dict (JSON) |
| 執行軌跡 | (包含在經驗中) | 攻擊執行過程 | Dict (JSON) |
| 評估指標 | (包含在經驗中) | 攻擊完成評估 | Dict (JSON) |

**資料流程**:
```
AICommander 
    → execute_attack()
    → 收集經驗資料
    → save_attack_experience()
    → ExperienceRepository
    → experience.db (SQLite)
```

**代碼範例**:
```python
# Core 模組中
from services.integration.aiva_integration.unified_data_manager import (
    get_unified_data_manager,
)

class AICommander:
    def __init__(self):
        self.integration_manager = get_unified_data_manager()
    
    async def execute_attack(self, target: str, attack_type: str):
        # 執行攻擊...
        result = await self._execute(target, attack_type)
        
        # 保存經驗
        self.integration_manager.save_attack_experience(
            plan_id=result.plan_id,
            attack_type=attack_type,
            ast_graph=result.ast_graph,
            execution_trace=result.trace,
            metrics=result.metrics,
            feedback={"reward": result.success_rate},
        )
```

#### 來源 2: Features 模組

**發送方**: `SQLiWorker`, `XSSWorker`, `IDORWorker`, 其他 Worker

| 資訊類型 | 接口方法 | 觸發時機 | 資料格式 |
|---------|---------|---------|---------|
| 漏洞發現 | `save_finding()` | 發現漏洞時 | FindingPayload |
| 驗證結果 | `save_finding()` | 驗證完成時 | FindingPayload |

**資料流程**:
```
SQLiWorker
    → test_sql_injection()
    → 發現漏洞
    → save_finding()
    → FindingRepository
    → PostgreSQL (findings 表)
    ↓
    → AttackPathEngine
    → attack_graph.pkl (NetworkX)
```

**代碼範例**:
```python
# Features 模組中
from services.aiva_common.schemas import FindingPayload
from services.aiva_common.enums import Severity, Confidence
from services.integration.aiva_integration.unified_data_manager import (
    get_unified_data_manager,
)

class SQLiWorker:
    def __init__(self):
        self.integration_manager = get_unified_data_manager()
    
    async def test_sql_injection(self, target_url: str):
        # 執行測試...
        if is_vulnerable:
            finding = FindingPayload(
                finding_id=f"sqli_{uuid4().hex[:8]}",
                affected_url=target_url,
                severity=Severity.CRITICAL,
                confidence=Confidence.HIGH,
                vulnerability_type="sql_injection",
                description="SQL Injection detected",
            )
            
            # 保存漏洞
            self.integration_manager.save_finding(
                finding=finding,
                scan_id=self.current_scan_id,
            )
```

#### 來源 3: Scan 模組

**發送方**: `NmapScanner`, `MasscanScanner`

| 資訊類型 | 接口方法 | 觸發時機 | 資料格式 |
|---------|---------|---------|---------|
| 資產資訊 | `add_asset_to_attack_graph()` | 發現資產時 | Dict |
| 漏洞資訊 | `add_vulnerability_to_attack_graph()` | 識別漏洞時 | Dict |

**資料流程**:
```
NmapScanner
    → scan_target()
    → 解析結果
    → add_asset_to_attack_graph()
    → AttackPathEngine
    → attack_graph.pkl (NetworkX)
```

### 接收方式

#### 方式 1: 直接調用 (推薦)

```python
from services.integration.aiva_integration.unified_data_manager import (
    get_unified_data_manager,
)

manager = get_unified_data_manager()

# 直接調用保存方法
manager.save_finding(finding, scan_id="scan_001")
```

**優點**: 
- 簡單直接
- 同步執行，可靠
- 適用於所有模組

**適用場景**: 所有模組

#### 方式 2: ExperienceManager 自動持久化 (Core 專用)

```python
from services.core.aiva_core.external_learning import ExperienceManager
from services.integration.aiva_integration.unified_data_manager import (
    get_unified_data_manager,
)

# 創建 ExperienceManager 並啟用自動持久化
manager = get_unified_data_manager()
exp_manager = ExperienceManager(
    auto_persist=True,            # 啟用自動持久化
    unified_manager=manager,      # 傳入整合模組管理器
)

# 記錄經驗（自動保存到整合模組）
exp_manager.push(state, action, next_state, reward)
```

**優點**: 
- 自動化
- 透明，無需手動調用
- 專為 Core 模組設計

**適用場景**: Core 模組的經驗記錄

### 提供給各模組的資訊

#### 提供給 Core 模組

**查詢接口**:

```python
# 1. 查詢高質量經驗
experiences = manager.query_high_quality_experiences(

stats = manager.get_experience_statistics()
# 返回: {
#     "total_experiences": int,
#     "average_score": float,
#     "attack_types": [
#         {"type": str, "count": int, "avg_score": float},
#         ...
#     ]

# 用途: Dashboard 顯示、趨勢分析

# 3. 導出訓練資料集
dataset_path = manager.export_training_dataset(
    attack_type="sqli",
    min_score=0.8,
    max_samples=1000,
)
# 返回: Path (JSONL 文件路徑)
# 用途: 模型訓練
```

**典型用途場景**:

```python
# AICommander: 基於歷史經驗優化策略
class AICommander:
    async def plan_attack(self, target: str, attack_type: str):
        # 載入歷史高質量經驗
        experiences = self.integration_manager.query_high_quality_experiences(
            attack_type=attack_type,
            min_score=0.85,
            limit=50,
        )
        
        # 分析成功模式
        successful_patterns = self._analyze_patterns(experiences)
        
        # 生成優化的攻擊計畫
        plan = self._generate_plan(target, successful_patterns)
        return plan
```

```python
# SQLiWorker: 基於歷史漏洞優化測試
class SQLiWorker:
    async def optimize_testing(self, target_url: str):
        # 查詢歷史 SQLi 漏洞
        historical_sqli = self.integration_manager.query_findings(
            vulnerability_type="sql_injection",
            status="active",
            limit=100,
        )
        
        # 分析相似目標
        similar_targets = [
            f for f in historical_sqli
            if self._is_similar(target_url, f["target_url"])
        ]
        
        if similar_targets:
            # 根據歷史調整 Payload
            self._adjust_payloads(similar_targets)
```
